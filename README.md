# EasyFlow 页面陪办助手 · 0.3.0

EasyFlow 是运行在真实网页上的浏览器扩展。用户打开网页、点击工具栏图标后，可以用文字提问，查看网页原文依据，或获得一次一步的操作指引。0.3.0 增加适老化帮助、术语解释、本机进度提醒和更明确的网页结果提示。

这是扩展源码仓库。本轮已将 0.3.0 部署到项目既有的 HTTPS 8090 下载入口，并核对公网版本、安装包哈希和模型代理健康接口。健康检查不等于完成一次实际 DeepSeek 对话，也不保证服务未来始终可用。

## 主要功能

- 当前页面问答：本地规则回答或可选在线智能；没有可靠依据时说明限制。
- 原文定位：滚动并高亮网页文字或控件；侧栏提供“关闭高亮”。
- 逐步指引：一次显示一个下一步，支持“我已完成”“我找不到”“我点错了”和重新规划。
- 切页恢复：标签页或地址变化后重新核对页面，让旧引用失效；跨站自动读取需要用户单独授权。
- 简明大字模式：放大文字和按钮，保留常用帮助入口。
- 页面帮助：根据当前页显示可问的问题、准备事项清单和常用术语解释，均可定位原文。
- 网页结果提示：分别识别已提交、审核中、审核通过、办结、退回和符合既有规则的预约确认；不会把“已提交”说成“已办成”。
- 本机进度提醒：主动保存简短目标、步骤和网站名称，7 天后失效；同网站恢复前重新读取，再按旧目标生成当前指引。
- 求助内容预览：可修改、复制文字给信任的人；不会自动发送。当前页面出现明确帮助入口时可定位查看。
- 语音能力：包含语音输入、授权引导和朗读界面；具体可用性取决于浏览器、语音服务、设备和权限。

更简短的功能清单见 [FEATURES.md](FEATURES.md)，版本变化见 [CHANGELOG.md](CHANGELOG.md)。

## 构建与测试

要求 Node.js 20 或更新版本。浏览器清单要求 Chrome 116 或更新版本；其他 Chromium 浏览器还需具备侧栏等相应 API。

先执行构建与核心自测：

```bash
npm ci
npm run build
npm run selftest
```

以下专项测试只需 Node 和项目依赖，不需要启动浏览器：

```bash
node --test scripts/senior-progress-selftest.mjs scripts/senior-assist-selftest.mjs scripts/senior-panel-selftest.mjs scripts/page-glossary-selftest.mjs scripts/page-outcome-selftest.mjs scripts/speech-ux-selftest.mjs
node --test scripts/model-integration-selftest.mjs scripts/page-access-selftest.mjs scripts/background-navigation-selftest.mjs scripts/conversation-navigation-selftest.mjs
```

`npm run build` 会先检查 TypeScript 类型，再重建 `dist/`，生成图标、脚本、样式和扩展清单，并执行清单检查。不要把个人文件存入 `dist/`。主自测会读取构建产物，因此需要先构建，再执行 `npm run selftest`。也可分别执行 `npm run typecheck` 或在构建后执行 `npm run verify`。

这组纯 Node 测试覆盖本机进度、适老帮助组件、术语、结果分类、语音状态、模型协议及切页后的请求与状态隔离。

持续高亮的 4 项浏览器测试需要单独配置。`scripts/highlight-sticky-browser-selftest.mjs` 当前在文件顶部硬编码了开发机的 Playwright 模块路径和 `browserPath` Chromium 可执行文件路径；Playwright 没有列入本项目的 npm 依赖，因此 `npm ci` 不会为此准备浏览器测试环境。换电脑后，需要先准备本机 Playwright 及兼容的 Chromium，再修改该测试脚本顶部的动态 `import` 路径和 `browserPath`。这些是测试环境路径，与扩展生产接口无关。

完成本机配置后，再执行：

```bash
node --test scripts/highlight-sticky-browser-selftest.mjs
```

`npm run test:senior` 会同时运行上述 59 项适老纯 Node 测试与 4 项浏览器高亮测试；尚未配置浏览器路径的新机器应使用前面的分组命令，不能直接把该汇总命令当作开箱即用的检查。自动化测试不替代原生侧栏、浏览器权限弹窗和真实麦克风验收。

## 安装扩展

1. 执行构建，或取得与该版本对应的扩展安装 ZIP 并解压。
2. 打开 `chrome://extensions`；Edge 可使用 `edge://extensions`。
3. 开启开发者模式，选择“加载已解压的扩展程序”。
4. 选择直接包含 `manifest.json` 的文件夹。自行构建时为 `dist/`。
5. 打开普通网页，点击工具栏里的 EasyFlow 图标。

更新已经安装的版本时，更新原扩展目录后，在扩展管理页点击“重新加载”，确认版本为 0.3.0，再刷新目标网页。若加载到新目录，请先停用旧副本，避免同时运行两个版本。源码仓库本身不是可以直接拖入浏览器安装的扩展包。

## 读取权限与切页

默认通过工具栏点击取得当前页面的临时访问权限。切换到尚未授权的标签页或跨站跳转后，可能需要再次点击 EasyFlow 图标。

设置中的“切页后继续协助”会请求普通 HTTP/HTTPS 网站的可选权限。只有浏览器确认授权后才启用；关闭时会请求撤销这项可选权限。跨页读取和“在线智能”是独立开关。

浏览器内部页面、扩展商店及其他受保护页面不能读取。扩展只采集主文档当前可见内容，不保证读取 iframe、地图、懒加载区域或复杂站点中的全部信息。

## DeepSeek 在线智能是可选功能

默认使用本地规则。用户在设置中开启“在线智能”后，扩展才会将经过过滤的页面摘要发送给配置的 HTTPS 模型代理。请求失败、返回格式不合要求或原文引用校验失败时会回退到本地规则。

模型服务地址在 `src/shared/model/config.ts`，对应访问范围在 `public/manifest.json`。当前源码保留项目已有的服务器配置；这只是客户端配置，不是服务健康或本次部署完成的证明。模型密钥应由服务器保管，不得放进扩展、源码仓库或安装包。

客户端的生产接口包括 `GET /health` 和 `POST /v1/dialogue`。对话结果使用 `result.kind`、`result.answer` 和 `result.evidence`，引用需包含当前页面的 `segmentId` 与连续原文 `quote`。扩展会同时检查摘要和当前页面元素。自建服务需要实现这一协议，并同步检查客户端地址和清单中的访问范围。

`scripts/model-proxy.mjs`、`scripts/model-proxy-lib.mjs` 与 `.env.example` 是旧版本地开发代理参考，使用较早的回复协议，不能直接当作当前生产后端。填入 `.env.local` 也不会让当前扩展自动连接本机代理。本仓库不包含生产服务器部署凭据或完整生产后端部署配置。

## 数据与操作边界

- 不读取输入框、文本域和下拉框的填写值；按钮值仅可能作为按钮文字兜底。
- 不代替用户点击、填写、勾选、提交、支付、处理密码或验证码。
- 页面高亮是定位辅助，不表示扩展已经执行该操作。
- 页面正文、原文引用、对话和计划主要保存在侧栏会话内存中；部分界面设置和简短目标使用浏览器本地存储。
- “保存进度”只保存经过检查的简短提醒，不保存网页正文、控件引用、聊天记录或成功凭据；它不会恢复旧 DOM，也不会自动把以前的步骤标为完成。
- 在线模式会过滤明显的证件号、手机号、银行卡号、邮箱等内容，但无法保证识别所有可见个人信息。是否发送当前页面摘要由用户决定。
- 术语解释来自本地通用词典，引用只证明该词出现在页面上；“未”“无需”等上下文会改变含义。
- 结果卡仅转述当前可定位的明确提示。有冲突或证据不足时不显示确定结果；提交成功不等于审核通过，审核通过不等于全部手续完成。
